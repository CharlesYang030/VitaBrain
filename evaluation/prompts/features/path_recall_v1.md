
## 已探索路径回溯（explored_path_recall_v1）
这是与普通动作完全独立的受控辅助。`spatial_memory.recall_candidates` 中的 `P###` 只表示智能体曾经实际占据过的历史站位或公开事件站位，不是物体坐标，也不是未来路线。地图上的青色 P 标记必须使用原样的 `node_id`。

每次决策只能二选一：普通动作（`decision_type="action"` 且 `return_request=null`），或 `decision_type: "return_to_visited"`。回溯时 `action` 必须为 null，并填写下面的选择字段；其他已开启功能要求的 plan_update、memory_updates 等字段仍须保留：
```json
{"decision_type":"return_to_visited","return_request":{"node_id":"P003","map_observation_id":"当前 observation_id","reason":"返回该历史点继续处理当前目标"},"action":null}
```
后端会在执行前检查同楼层、地图和观察是否仍有效、旧路线的门和终点是否仍可达。检查失败不会移动、不会生成新画面，只返回受控原因（例如 `recall_door_closed`、`recall_route_blocked`、`recall_map_stale`）。条件没有改变时不要重复同一失败请求，应根据反馈改走普通动作。回溯检查只验证已走路段，失败不说明所有可能路线都不存在。

检查通过后才会执行一次审计过的回溯，并重新采集当前三视图和地图。成功回执会说明回到了哪个 P 节点、当时的公开事件、触发原因、前后 observation_id、回溯距离，以及当前任务目标；这只是位置回溯，不代表任何子任务完成。该辅助使用一次定位，省略沿途行走的仿真时间与风险，不得当作未经辅助的导航成绩。一次回溯占用一个模型决策，内部定位不计作普通原子动作。回溯不会跨楼层，跨楼层必须使用真实楼梯或电梯。不要声称到达未列出的节点或任务已经完成。


可携带当前手持物回溯；恢复历史位置、朝向与视线，保留当前物品、内容和任务状态，不是世界状态回退。

导航选择优先级：眼前可完成任务操作就先操作；需返回已探索位置时，优先直接选相关P点回溯，不要为旧路反复转身或逐步行走。支线结束、送回物品、绕路后返回、困在角落或重复微调时，主动检查P点与distance_from_current_m；无需自己证明一定可达，后台会检查。探索新区域再用点选导航（若已开启）。不要回溯到几乎重合的当前点；同条件失败不重复。近邻P点会保留ID并更新为最近一次真实站位及朝向，按本轮候选表为准。
